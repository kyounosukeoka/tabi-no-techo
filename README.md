# 旅の手帖 — 旅程表・すごろく・思い出

スマートフォン優先の日本語Webアプリです。**GitHub Pagesに置くだけで動作**します。ビルドやAPIキーは必要ありません。

## 主な機能

- 旅行の新規作成・編集、旅行一覧と表紙写真
- 日別の旅程表（時刻 / 予定 / 写真）、予定の費用・場所・メモ・訪問状況
- 予定から自動生成する**すごろくマップ**（9:16、2種類の自動配置、上下連結と縦スワイプ、訪問チェック）
- 目的地の上下・左右位置を含む**AI背景画像用プロンプト**の自動生成・コピー
- ChatGPTなどで別途作成した背景画像をマップに取り込み、マスと道を重ねる機能
- 支出管理、均等・個別金額の割り勘、立替精算、精算履歴
- 旅行後の写真アルバムとコメント
- 旅のしおり / スクラップブックの**A4縦PDFを直接ダウンロード**
- 写真込みのJSONバックアップ・復元
- オフライン対応のPWA（インストール後、保存済みの情報を使用）

## GitHub Pagesへの公開方法

1. GitHubに新しいリポジトリ（例：`tabi-no-techo`）を作成します。
2. このZIPを**展開**し、`index.html`、`styles.css`、`app.js`、`pdf.js`、`manifest.webmanifest`、`sw.js`、`assets`フォルダなど、**中身をリポジトリの最上位にアップロード**します。ZIPだけをアップロードしても公開できません。
3. GitHubのリポジトリの **Settings → Pages** を開きます。
4. **Build and deployment → Deploy from a branch**、Branchを `main`、フォルダを `/(root)` にして Save を押します。
5. 公開された `https://ユーザー名.github.io/リポジトリ名/` をSafariやChromeで開きます。
6. iPhoneならSafariの共有メニューから「ホーム画面に追加」でアプリのように使えます。

ページの反映には少し時間がかかる場合があります。更新後に古い画面が表示されたら、ページの再読み込みをお試しください。

## 最初の使い方

1. ホームの **「新しい旅を作る」** で、旅行タイトル・日付・行き先を登録します。
2. **「しおり」** で日別に予定を登録します。予定写真や予定費用も追加できます。
3. **「すごろく」** で自動配置されたマスを確認します。奇数ページは左下、偶数ページは右下スタート。マップを指で下に引くと上の次ページ、上に引くと前ページへ移動します。上下移動ボタンもあります。
4. **「AI画像用プロンプト」** をコピーして画像生成AIに貼り付け、生成した画像を**「背景画像を登録」** から取り込みます。AI画像生成そのものはこのアプリ内では実行しません。
5. **「費用」** で参加者と支出を登録し、割り勘・立替額を確認します。
6. **「アルバム」** で写真を貼り付け、しおり・アルバムからA4 PDFを作成します。
7. **「設定・バックアップ」** から定期的にJSONファイルを保存してください。

はじめに「サンプル旅行を試す」を選択すると、予定・すごろくの操作を確認できます。これはダミー旅行です。

## 保存とプライバシー

- データは、利用中のブラウザの **IndexedDB** に保存されます。サーバーには送信しません。
- iPhoneのSafariとホーム画面アプリでは、環境によって保存領域が別になることがあります。相互移行にはバックアップを利用してください。
- ブラウザデータの削除、端末変更、プライベートモードではデータが消える可能性があります。**自動クラウド同期はありません**。
- 写真や生成した背景は自動縮小して保存されますが、大量の写真を登録すると端末の保存容量を消費します。
- バックアップJSONには写真・名前・費用も含まれます。第三者へ安易に共有しないでください。
- AIプロンプトを外部AIへ貼り付ける際は、旅行先や旅程が外部サービスに共有される点をご確認ください。

## PDFについて

A4縦（210×297mm）のPDFを**ブラウザ内で生成**するため、PDFライブラリのCDNや印刷ダイアログは不要です。日本語はCanvasで描画された画像としてPDFに格納されるため、**PDFの文字検索・コピーはできません**。写真が多いとPDFの容量が大きくなる場合があります。

## 初期版の範囲・今後の拡張

- 旅行メンバーのリアルタイム共同編集、ログイン、Supabase連携はまだ搭載していません。
- すごろく用AI画像生成は**プロンプトコピー → 外部画像生成 → 取り込み**方式です。API料金をかけずに使えます。
- すごろく背景はAIの厳密なピクセル座標遵守を保証しません。マスや経路はアプリ側で正確に描画します。
- 地図APIによるルートや所要時間の自動計算はまだ搭載していません。
- 自動更新される交通・営業時間などのリアルタイム情報はありません。

## ファイル構成

```text

sw.js               オフラインPWAキャッシュ
manifest.webmanifest PWA定義
assets/             アプリアイコン
.nojekyll           GitHub Pages対応
```


## 更新履歴

### Ver.1.1.0：上下連結のすごろく
- 最大5マスずつ、奇数ページは左下→右→左→右→左上、偶数ページは右下→左→右→左→右上に自動配置。テンプレートの手動選択は廃止。
- 各ページは9:16で、次ページを上に実際に積み重ねる。内部スクロールで縦に移動し、上下端の横中央で経路が接続する。
- 最初のページにSTART、最終ページの最後の予定にGOALを表示。5件未満のページには存在する予定だけを配置。
- AI画像プロンプトは座標表や装飾矩形の代わりに、目的地ごとの左右・高さと順序を指定。背景のみに限定する。
- 既存の旅行データと背景画像は保持する。旧テンプレート設定は新配置に置き換わり、旧背景には再生成の案内が出る。
- 画像を切り取らず全体をマップ枠に合わせるため、9:16以外の画像は縦横比が変化する。なるべく9:16の画像を使用する。


### Ver.1.0.1：AIすごろく背景プロンプトの上下方向を明確化
- 画像座標の原点を左上 (0,0)、Yは下向きに増加すると明記。
- すごろくの進行方向は原則として下から上（P01が下側）と説明。
- 各予定名とP番号・X/Y座標・画面内での上下左右位置を一対一で表示。
- ランドマークを対応するマスの近辺に置き、マス中心の保護範囲には描かないよう指示。
- 上下反転・180度回転・左右反転を禁止。
- 既存旅行データ、すごろくのマス配置、登録済み画像には変更を加えません。

既に生成した背景画像は自動修正されません。必要なページで「AI画像用プロンプト」を再生成し、画像生成サービスで作成し直してから背景画像を差し替えてください。
